# About This Project

NeuroStack Documentation is a portfolio project that demonstrates how I approach technical writing for a cloud ML platform.

NeuroStack is a fictional product. The documentation was created from scratch to simulate a technical writer working with an evolving product and incomplete specifications.

---

## Why I Built It

I wanted to practice the full documentation workflow, not just writing individual pages:

- turning product requirements into a consistent product model;
- designing information architecture around user needs and workflows;
- writing different types of documentation for different audiences;
- maintaining documentation as code with Git.

---

## How I Worked on the Project

I started by defining the product scope: core resources, user roles, workflows, and technical constraints.

Where the product specification was incomplete, I used an AI developer simulator to clarify how the platform should work. I treated these discussions as developer/product input, then made and recorded the resulting decisions in PRODUCT_DECISIONS.md.

The documentation was then developed in iterations:

1. Define and refine the product model
2. Identify documentation audiences, user journeys, and content types
3. Design the documentation information architecture
4. Write and revise documentation in Markdown
5. Validate content against the established product model and resolve inconsistencies
6. Track changes and documentation history with Git

---

## What the Project Demonstrates

The documentation set includes:

- product overview and architecture;
- onboarding and end-to-end ML workflows;
- concepts and terminology;
- tutorials and task-oriented how-to guides;
- API and CLI reference;
- troubleshooting and error documentation;
- best practices and release notes.

The project focuses on information architecture, user-oriented technical writing, documentation consistency, and Docs-as-Code workflows.

---

## Project References

The documentation structure and writing approach were informed by established cloud documentation, including Google Cloud, AWS, and Cloud.ru, as well as the Write the Docs community.

For the product model and the reasoning behind documentation decisions, see [PRODUCT_DECISIONS.md](PRODUCT_DECISIONS.md).
